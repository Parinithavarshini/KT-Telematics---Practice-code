Web app
    -Front end (Client side - Browser(client)) - HTML,CSS,JS
    -Back end (Server side)

Node js-run time environment allows js to run outside browser

Before node js:
    Javascript - only in browser (frontend)
    Backend - Java, Python, PHP, Ruby
After node js:
    Both frontend and backend

Created by - Ryan Dahl (2009)
Before node => each user = one thread,1000 user = 1000 threads,too much memory usage
Node js =>Single thread,asynchronous and event driven

Node js is built by:
    1.v8 engine
        Converts js code to machine code
    2.libuv
        handles file system operations and network req
    3.Event loop 
        Decides what to run next

Node js - other than v8 we have some features
    1.read or write files
    2.Connect with db
    3.Acts like a server (eg : in front end we submit a form and request goes to backend(server))
          --handles req and response
    
    Cons:
        1.DOM Manipulation not possible (because we run in server side)

Browser has window object - it has document,setTimeout and other things
Same like the window object in browser,we have -- global object-- in node js

Key features:
    -Fast execution - built on v8 engine
    -Non-blocking (asynchronous) - Handles multiple user same time
    -File system access
    -Same language for frontend and backend
    -node package manager - ready made code downloading tool (express - create server easily,axios-send http req)
    -single threaded but handles multiple tasks

async tasks-> browser -> web api
              node -> libuv
after completing async task result is stored in callback queue
event loop is like manager call stack free - execute async task
                           call stack full - wait

Working of node js:
    1.Event driven model 
        -waits continuously and if event triggered it executes
        1->Event emitter - event is triggered
        2->Event Listener - if event occurs callback is called
        3->Event loop 
    2.Non blocking I/O
        Does not wait for async tasks continuously do the work

Node.js Execution flow
Request
   ↓
Event Queue
   ↓
Event Loop
   ↓
Call Stack (sync)
   ↓
Async → libuv (background)
   ↓
Callback Queue
   ↓
Event Loop
   ↓
Call Stack
   ↓
Response

Streams and buffers:
Heap memory - memory where node js sores objects,variables and functions.
            heap has fixed memory if overflow app will crash

Buffer - temporary memory to store data
    -videos,images,files - binary data ,js cannot handle it so stored in buffers
Stream - process of transporting data as smaller chunks

Client sent request
        ↓
Request sent to server
        ↓
Server sends video as smaller chunks
        ↓
Each chunk stored in BUFFER
        ↓
Video player plays immediately
        ↓
Next chunks come and video plays continuously

4 types of streams:
    Readable - get data (server reads the data)
    Writable - send data (server give response)
    Duplex - both read and write
    Transform - data modify
